# 0002. Mail tokens

## Summary

Magic link signs in a known person. Reset lets them set a password. Invite still needs an existing person and now also mails the church code. The request writes an outbox row. The worker sends through Resend.

## Requirements

**User stories**:
- As a person, I want a link in my inbox when I forgot the password.
- As a pastor, I want the invite they already get in the app to also show up in mail.

**Acceptance criteria**:
- **AC-M1**: `POST /session/link` for a known email sets `consumed_at` on any unused magic row, inserts one (`expires_at` now plus 60 minutes), and writes `mail` outbox in the same `apply`. Unknown email writes nothing and still redirects with `?err=mail`.
- **AC-M2**: Guest `GET /session/link/{id}?t=` looks up the row, checks SHA-256 hex of the mailed `t` string, checks expiry and `consumed_at`. A hit consumes, mints a session, goes to Home. A miss is `?err=miss`. Signed in GET is 303 `/home` and does not consume.
- **AC-M3**: `POST /session/reset` is the same quiet shape as magic, with 24 hour expiry on `password_resets`.
- **AC-M4**: Guest `GET /session/reset/{id}?t=` paints Set a new password when the token is live. Guest `POST` with `t` and a passing password consumes, writes the hash, deletes every session, mints one, goes to Home. Signed in GET is 303 `/home` and does not consume.
- **AC-M5**: `incr_rate_window("rate:mail:{normalized_email}", 3600)` allows 5 hits. Plus `RateKind::Session` on the client key (today's 10 per 60s). A refuse is still `?err=mail`.
- **AC-M6**: Invite (`invite_member`) on a known person writes outbox `{to,subject,text}` with the church name, `invite_code`, and `{origin}/churches`. Unknown email stays today's quiet `StoryOk` and writes no outbox. No new token table. No GET `/invites` page.
- **AC-M7**: Worker `kind = mail` POSTs `https://api.resend.com/emails` with Bearer `RESEND_API_KEY`, JSON `from` (`RESEND_FROM`), `to`, `subject`, `text`. Header `Idempotency-Key: mail/{outbox_id}`. Local missing key marks `done` without a call. Public process missing key, From, or public URL refuses boot. Origin in links is `ECCLESIA_PUBLIC_URL` on a public host, else the listen origin the App passes into the story.
- **AC-M8**: After 8 failed sends the row is dead. The person is not told. They can request again.

## Decision

Two token tables, hashed secrets, outbox then Resend. Invite reuses `invite_code`.

## Feature design

**Data model sketch**:
`magic_links` and `password_resets` as in the umbrella. Outbox payload JSON.

**State transitions**:
Mint → consume or expire. New request retires unused. Worker pending → working → done or dead.

**API surface**:
See umbrella table for `/session/link` and `/session/reset`. Invite stays `POST /churches/{id}/invite`.

**Value sourcing**:

| Action | Value produced | Source |
|---|---|---|
| Raw `t` | 32 bytes as base64url, no pad | SDK `rand` |
| `token_hash` | hex SHA-256 of that mailed string | SDK, not argon2 |
| Link | `{origin}/session/link/{id}?t=` or reset path | Public env, else App listen origin |
| Mail `subject` / `text` | fixed strings in the SDK story | Magic: subject `Your sign in link`. Reset: `Set a new password`. Invite: `Invite to {church}`. `text` is one or two short sentences plus the URL or code. Follow `docs/PROSE.md`. |
| Invite redeem | existing church page | `{origin}/churches`. They type the code into the redeem form already on that page. |
| Idempotency | `mail/{outbox_id}` | outbox id the story just wrote |

**Key invariants**:
- Never store raw `t`.
- Never log `t`.
- Magic does not create a user.
- Prefetch on GET may consume. They request again.

**Security model**:
Guest only for link and reset. Signed in POST to those doors redirects Home. Invite is governor plus existing membership rules.

**Configuration required**:
`RESEND_API_KEY`, `RESEND_FROM`, `ECCLESIA_PUBLIC_URL` on a public host.

**Critical test scenarios**:
- Happy path: known email, outbox `mail` pending, worker with a test hub marks done. Verifies **AC-M1**, **AC-M7**
- Happy path: consume magic, Home signed in. Second GET is `Try again.` Verifies **AC-M2**
- Failure: unknown email, no token row, same flash. Verifies **AC-M1**
- Failure: public boot without `RESEND_API_KEY` exits. Verifies **AC-M7**
- Auth: invite unknown email is quiet `StoryOk`, no outbox. Verifies **AC-M6**

## Build plan

1. Token tables and request/consume stories without the vendor. Satisfies **AC-M1** to **AC-M5**, **AC-M8** (store side)
2. Worker Resend send and public env. Satisfies **AC-M7**, **AC-M8**
3. Invite outbox. Satisfies **AC-M6**

## Consequences

**Positive**:
- Request time stays off the vendor, like push.

**Negative / tradeoffs**:
- GET consume plus prefetch.
- Quiet mail means a typo looks like success.

**Neutral**:
- Outbox `mail` kind is no longer reserved only.

## Rationale

Resend skill says retry without an idempotency key doubles mail. The outbox id is stable across the 8 worker tries. `reqwest` is already in the SDK. A second crate is noise. Invite already has a code, so mail is a notice they can also read offline, not a new token species.
